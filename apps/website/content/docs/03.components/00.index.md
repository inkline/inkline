Inkline ships eight components. Each one is authored once in `.ink.tsx` and
compiled to seven native framework packages, so the props, events and slots
below are the same whichever package you install.

Every page in this section is a reference: what the component is, a live example
rendered from that framework's own Storybook, and the complete props / events /
slots surface.

## The eight components

| Component                                          | Import         | What it is                                                   |
| -------------------------------------------------- | -------------- | ------------------------------------------------------------ |
| [Badge](/docs/components/badge)                     | `IBadge`         | A small inline label for counts, statuses and tags.            |
| [Button](/docs/components/button)                   | `IButton`        | A clickable action element with loading and disabled states.   |
| [Checkbox](/docs/components/checkbox)               | `ICheckbox`      | A labelled boolean control, with a partially-checked state.    |
| [Field group](/docs/components/field-group)         | `IFieldGroup`    | Joins bordered controls into one unit with merged seams.       |
| [Hamburger menu](/docs/components/hamburger-menu)   | `IHamburgerMenu` | An icon-only disclosure toggle whose bars morph while open.    |
| [Input](/docs/components/input)                     | `IInput`         | A text field with inline prefix/suffix addons and a textarea mode. |
| [Radio group](/docs/components/radio)               | `IRadioGroup`    | A single-select group rendered from an options array.          |
| [Switch](/docs/components/switch)                   | `ISwitch`        | An on/off toggle announced as a `switch` to assistive tech.    |

## Styled and headless

Every component ships in two layers, from two entry points.

**Styled** — the batteries-included component. Import it from the package root:

```ts
import { IButton } from "@inkline/react";
```

It carries the appearance, which comes from [Styleframe](/docs/getting-started/theming)
recipes rather than baked-in CSS, so you restyle it by changing tokens instead of
overriding rules.

**Headless** — the same structure, state and accessibility wiring with no classes.
Import the parts from the `/headless` subpath:

```ts
import { IButtonBase } from "@inkline/react/headless";
```

Use the headless layer when you want the component's mechanics under your own CSS.
Each styled component is composed from one or more headless parts; the
**Composition** section on every page names them. See
[Your first component](/docs/getting-started/first-component#drop-the-styling-the-headless-layer)
for a worked example.

## How to read the reference tables

**Props.** Types are written exactly as the compiler resolves them — full string
literal unions, never abbreviated to `string`. A prop with no default is written
`—`; it is optional and `undefined` unless you pass it.

Styling props (`color`, `variant`, `size`, `orientation`, and so on) come from
the component's Styleframe recipe, not from its component source. Their unions
and their defaults are the recipe's, and they change when you change the recipe.

**Events.** Components with two-way state expose it as a prop plus a paired
`update:<prop>` event, so the binding works idiomatically in each framework —
`v-model` on Vue, `bind:` on Svelte, a value/handler pair on React. Both halves
are listed.

**Slots.** A component with a `default` slot that also takes a `label` prop uses
the prop as the slot's fallback: pass either, and the slot wins.

## What the examples show

Each page embeds live stories from the deployed Storybook for all seven
frameworks, one per tab. The same story is compiled for every target, so the tabs
are a direct comparison rather than seven hand-written snippets.

Two targets have differences worth knowing before you copy an example — Angular's
`klass` prop on headless components, and Astro's static-only rendering, which
lowers two-way bindings to one-way. Both are covered in
[Framework support](/docs/getting-started/framework-support).
