The Input is a text field with color, variant and size options, optional inline
`prefix` and `suffix` addons, and a two-way `value`. Setting `type="textarea"`
swaps the native `<input>` for a `<textarea>` without changing the API.

## Props

| Prop          | Type                                | Default     | Description                                                    |
| ------------- | ----------------------------------- | ----------- | -------------------------------------------------------------- |
| `value`       | `string`                            | —           | Two-way field value. Pairs with the `update:value` event.      |
| `color`       | `"light" \| "dark" \| "neutral"`    | `"neutral"` | Color variant.                                                 |
| `variant`     | `"default" \| "soft" \| "ghost"`    | `"default"` | Style variant.                                                 |
| `size`        | `"sm" \| "md" \| "lg"`              | `"md"`      | Size variant, shared by the shell and the addons.              |
| `invalid`     | `"true" \| "false" \| boolean`      | `"false"`   | Invalid-state styling.                                         |
| `type`        | `string`                            | —           | Native input type. `"textarea"` renders a `<textarea>` instead. |
| `placeholder` | `string`                            | —           | Placeholder text.                                              |
| `id`          | `string`                            | —           | Id of the native control.                                      |
| `name`        | `string`                            | —           | Name of the native control, used for form submission.          |
| `disabled`    | `boolean`                           | —           | Disables the control, and selects the disabled styling.        |
| `readonly`    | `boolean`                           | —           | Marks the control read-only, and selects the read-only styling. |

`id`, `name`, `type`, `placeholder`, `disabled` and `readonly` are declared on
`InputControlBaseProps`; `color`, `variant`, `size` and `invalid` come from the
`input` Styleframe recipe, so their unions and defaults are the recipe's.

`disabled` and `readonly` are a deliberate exception: the recipe types them as
`"true" | "false" | boolean`, but the Input narrows them to `boolean` so the same
prop can drive both the native attribute and the recipe axis.

To attach controls *outside* the field — a button, a select, a badge — wrap them
together in a [Field Group](/docs/components/field-group).

## Events

| Event          | Payload  | Description                                        |
| -------------- | -------- | -------------------------------------------------- |
| `update:value` | `string` | Fired on every keystroke, with the field's new value. |

`value` and `update:value` are the two halves of one `defineModel`. In frameworks
that support it, bind them together with the binding idiom; on the static Astro
target the binding lowers to one-way (INK0045).

## Slots

| Slot     | Description                                                  |
| -------- | ------------------------------------------------------------ |
| `prefix` | Inline content before the control. Its wrapper is only rendered when the slot is filled. |
| `suffix` | Inline content after the control. Its wrapper is only rendered when the slot is filled.  |

The Input has **no default slot** — its content is the native control.

## Composition

`IInput` is a styled wrapper around five headless parts: `IInputBase` (the
shell), `IInputControlBase` (the native `<input>`, which owns the value),
`IInputTextareaBase` (its `<textarea>` sibling), and `IInputPrefixBase` /
`IInputSuffixBase` (the addon wrappers). Import them from
`@inkline/<framework>/headless` when you want the mechanics under your own CSS —
see
[Your first component](/docs/getting-started/first-component#drop-the-styling-the-headless-layer).
