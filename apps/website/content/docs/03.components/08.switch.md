The Switch is an on/off toggle. It is a native `<input type="checkbox">` with
`role="switch"`, styled as a sliding track, with a two-way `checked` state and a
text label that supplies its accessible name.

## Props

| Prop       | Type                             | Default     | Description                                                      |
| ---------- | -------------------------------- | ----------- | ---------------------------------------------------------------- |
| `checked`  | `boolean`                        | —           | Two-way on/off state. Pairs with the `update:checked` event.     |
| `label`    | `string`                         | —           | Label text; overridden by the default slot.                      |
| `color`    | `"light" \| "dark" \| "neutral"` | `"neutral"` | Off-state track color.                                           |
| `size`     | `"sm" \| "md" \| "lg"`           | `"md"`      | Size variant, applied to both the shell and the track.           |
| `id`       | `string`                         | —           | Id of the native control.                                        |
| `name`     | `string`                         | —           | Name of the native control, used for form submission.            |
| `disabled` | `boolean`                        | —           | Disables the control.                                            |
| `readonly` | `boolean`                        | —           | Shows the state but blocks the toggle; the switch stays focusable. |

`id`, `name`, `disabled` and `readonly` are declared on
`SwitchControlBaseProps`; `label` on `SwitchProps`. `color` and `size` come from
the `switch-field` Styleframe recipe, so their unions and defaults are the
recipe's.

`readonly` differs from `disabled`: a read-only switch is still focusable and
still submits with the form, it just refuses to flip. A native checkbox ignores
the HTML `readonly` attribute, so this is enforced behaviourally and announced
with `aria-readonly`.

Space toggles the switch natively; Enter is handled explicitly, so the whole
keyboard map matches the ARIA switch pattern.

## Events

| Event            | Payload   | Description                                     |
| ---------------- | --------- | ----------------------------------------------- |
| `update:checked` | `boolean` | Fired when the user toggles the switch. |

`checked` and `update:checked` are the two halves of one `defineModel`. In
frameworks that support it, bind them together with the binding idiom; on the
static Astro target the binding lowers to one-way (INK0045).

## Slots

| Slot      | Description                                                    |
| --------- | -------------------------------------------------------------- |
| `default` | Label content. Falls back to the `label` prop when left empty. |

## Composition

`ISwitch` is a styled wrapper around three headless parts: `ISwitchBase` (the
`<label>` shell), `ISwitchControlBase` (the native input that owns the state and
the keyboard map) and `ISwitchLabelBase` (the text). Import them from
`@inkline/<framework>/headless` when you want the mechanics under your own CSS —
see
[Your first component](/docs/getting-started/first-component#drop-the-styling-the-headless-layer).
