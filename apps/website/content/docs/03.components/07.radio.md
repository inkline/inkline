The Radio Group is a complete single-select control. You give it an `options`
list and it renders one radio per entry, owns the two-way `value`, and derives
each radio's checked state from it — so exactly one option is selected at a time.

## Props

| Prop          | Type                             | Default     | Description                                                           |
| ------------- | -------------------------------- | ----------- | --------------------------------------------------------------------- |
| `value`       | `string`                         | —           | Two-way selected value. Pairs with the `update:value` event.          |
| `options`     | `RadioOption[]`                  | `[]`        | The options rendered as radios.                                       |
| `name`        | `string`                         | —           | Shared control name, which enables native mutual exclusivity.         |
| `color`       | `"light" \| "dark" \| "neutral"` | `"neutral"` | Color variant, applied to each radio's control.                       |
| `size`        | `"sm" \| "md" \| "lg"`           | `"md"`      | Size variant.                                                         |
| `orientation` | `"vertical" \| "horizontal"`     | `"vertical"` | Layout orientation.                                                  |
| `disabled`    | `boolean`                        | —           | Disables every option in the group.                                   |
| `readonly`    | `boolean`                        | —           | Shows the selection but blocks changes; the controls stay focusable.  |
| `id`          | `string`                         | —           | Id of the group element.                                              |
| `label`       | `string`                         | —           | Accessible name for the group, exposed as `aria-label`.               |

`id`, `label` and `readonly` are declared on `RadioGroupBaseProps`; `options`,
`name`, `disabled` and `readonly` on `RadioGroupProps`. `size` and `orientation`
come from the `radio-group` Styleframe recipe and `color` from the `radio-field`
recipe, so their unions and defaults are the recipes'.

`RadioOption` is:

| Field      | Type      | Description                                  |
| ---------- | --------- | -------------------------------------------- |
| `value`    | `string`  | The value submitted when this option is selected. |
| `label`    | `string`  | Visible label. Falls back to the value.      |
| `disabled` | `boolean` | Disables just this option.                   |

## Events

| Event          | Payload  | Description                                             |
| -------------- | -------- | ------------------------------------------------------- |
| `update:value` | `string` | Fired when an option is selected, with that option's value. |

`value` and `update:value` are the two halves of one `defineModel`. In frameworks
that support it, bind them together with the binding idiom; on the static Astro
target the binding lowers to one-way (INK0045).

## Slots

The Radio Group has no slots — its content is generated from `options`.

## Composition

`IRadioGroup` is a styled wrapper around three headless parts:
`IRadioGroupBase` (the `<div role="radiogroup">` container), `IRadioBase` (the
`<label>` for one row) and `IRadioFieldBase` (the native radio input). Import
them from `@inkline/<framework>/headless` when you want the mechanics under your
own CSS, or when you need a row layout the `options` list can't express — see
[Your first component](/docs/getting-started/first-component#drop-the-styling-the-headless-layer).
